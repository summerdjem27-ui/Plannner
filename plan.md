# План реализации «Моего планировщика»

План основан только на требованиях из `tz.md`. Реализация выполняется последовательно: каждый следующий шаг начинается после завершения и проверки предыдущего. Итоговое приложение состоит из `index.html`, `styles.css` и `script.js`; внешние библиотеки, CDN и дополнительные функции не добавляются.

## Общий порядок проверки

После каждого шага приложение должно открываться без необработанных ошибок в консоли. Автоматические проверки выполняет разработчик или нейросеть: пользовательские данные для тестов создаются в отдельном тестовом состоянии `localStorage` и после проверки удаляются. Временные тестовые файлы, если они понадобятся исполнителю, не входят в результат и удаляются до сдачи.

Ручная проверка пользователя проводится только там, где нет объективного автоматического критерия: визуальная иерархия, приятность оформления, удобство размеров и ощущение от взаимодействия.

## Шаг 1. Основа приложения, даты и локальное состояние

**Статус: выполнен 20 августа 2026 года.**

### История выполнения

Созданы `index.html`, `styles.css` и `script.js`. Реализованы автономный каркас всего экрана, локальные даты, текущая неделя с понедельника по воскресенье, выбор дня, переходы между неделями, кнопка «Сегодня», начальная отрисовка центрального дня и семи компактных карточек. После загрузки всегда выбирается сегодняшний день; в соседней неделе — понедельник.

Реализовано единое состояние `myWeeklyPlanner` версии `1`: создание, нормализация, чтение и запись, резервирование повреждённого JSON, чистое восстановление и отдельное предупреждение при недоступном хранилище. Добавлены `revision`, `updatedAt`, `lastWriterId`, уникальный `tabId`, применение операций к свежему состоянию, Web Locks при наличии и обработка внешних изменений через `storage`. Панели «Входящие» и настроек открываются и закрываются; формы функций следующих шагов пока намеренно отключены.

`script.js` разделён на предусмотренные ТЗ секции: константы, даты, хранилище, операции, выборки, отрисовка, события, drag-and-drop, панели и инициализация. Пользовательские значения в динамической разметке выводятся через `textContent`.

Автоматически проверено:

- синтаксис `script.js` встроенным Node.js;
- наличие трёх файлов приложения, отсутствие CDN и внешних URL;
- отсутствие повторяющихся HTML `id`;
- парность фигурных скобок CSS;
- формирование недель на границе месяца и года, включая неделю `29.12.2025–04.01.2026`;
- корректная неделя для високосной даты `29.02.2024` и отклонение несуществующей даты `29.02.2025`;
- семь последовательных дат с понедельника по воскресенье;
- переходы на соседние недели, выбор дня и возврат кнопкой «Сегодня»;
- повторная загрузка с выбором сегодняшнего дня;
- открытие и закрытие панелей;
- сохранение и восстановление состояния;
- резервная копия повреждённого JSON и уведомление о восстановлении;
- передача изменения между двумя изолированными вкладками без перезагрузки;
- сохранение двух несвязанных изменений и правило «последняя запись побеждает» для одной сущности;
- использование блокировки `myWeeklyPlanner-write`, когда Web Locks API доступен;
- отсутствие ошибок во время изолированного автоматического прогона.

Нюанс среды разработки: встроенное управление реальным браузером не запустилось из-за системного запрета доступа к профилю приложения. Поэтому DOM-логика была проверена в изолированной среде, но фактическая отрисовка в браузере, сетка, переполнение и визуальное поведение фокуса автоматически не подтверждены. Обычная команда `node` отсутствовала в `PATH`; для синтаксической и логической проверки использован встроенный Node.js рабочего пространства. Временный тестовый файл после успешного прогона удалён.

Добавления сверх плана: новых продуктовых функций не добавлено. Для надёжности в пределах требований шага отдельно различены два случая загрузки: повреждённые данные и полностью недоступное хранилище; для них показываются разные уведомления.

### Доработка шага 1 после ручной проверки

По обратной связи пользователя название изменено с «Мой планировщик» на **«Мой квест на неделю»**, а подпись «Спокойный план на неделю» удалена. Ноутбучная компоновка перестроена: крупный выбранный день расположен слева, недельный маршрут — справа. В правой колонке одновременно находятся заметный недельный прогресс, главное дело, цель и сетка всех семи дней. Высота рабочей области привязана к высоте окна; при нехватке места прокручивается содержимое соответствующего блока, а не вся основная страница. На ширине до 980 px интерфейс последовательно складывается в одну колонку, поскольку уместить обе части рядом без потери читаемости невозможно.

Недельный прогресс получил крупный счётчик, доступную полосу `progressbar` и процентное заполнение. Добавлена короткая фраза недельной мотивации с пятью состояниями: нет задач, ничего не выполнено, выполнено меньше половины, выполнена большая часть и завершены все задачи. Это дополнение сверх первоначального шага внесено по прямой обратной связи пользователя и остаётся в границах требований ТЗ о недельном прогрессе и мотивации.

После перестройки повторно проверены синтаксис JavaScript, наличие всех DOM-элементов, к которым обращается скрипт, уникальность HTML `id`, парность блоков CSS и отсутствие внешних зависимостей. Фактическую вместимость на конкретном экране и визуальное ощущение новой композиции по-прежнему необходимо проверить вручную в браузере.

### Вторая доработка шага 1 после ручной проверки

По новой обратной связи бежевая палитра полностью заменена на мятно-зелёную шкалу уровней 0–5. Уровни 0–1 используются для фона и больших поверхностей, 2 — для подложек и границ, 3 — для выбранных состояний, 4 — для активных элементов и прогресса, 5 — только для небольших сильных акцентов. Текст переведён в тёмный зелёно-графитовый диапазон; предупреждения оставлены приглушённо-коралловыми. Соответствующие требования синхронно изменены в `tz.md`.

Причина оставшейся прокрутки всей страницы: прежняя высота рабочей области рассчитывалась отдельно и вместе с шапкой, внешними отступами и нижним полем могла превышать высоту окна. Для ширины от 821 px корневой экран теперь построен как CSS Grid высотой ровно `100vh`; `html`, `body` и основная рабочая область не прокручиваются. Прокрутка разрешена только внутри реально переполненного списка задач или недельной карты. На ширине до 820 px остаётся обычная вертикальная прокрутка, необходимая для последовательной мобильной компоновки.

После изменения повторно проверены синтаксис JavaScript, соответствие всех JS-селекторов существующим HTML-элементам, уникальность `id`, парность CSS-блоков, отсутствие прежних бежевых значений и внешних зависимостей. Реальное отсутствие полосы прокрутки на конкретном ноутбуке требует повторной ручной проверки, так как встроенный браузер среды разработки недоступен.

### Третья доработка шага 1 по визуальному референсу

Пользователь передал референс недельной панели с крупным обзорным рядом и семью дневными карточками снизу. Компоновка адаптирована к функциям проекта без копирования лишних элементов референса: аккаунт, язык, отдельные разделы меню и новый аналитический график не добавлялись. В верхнем ряду теперь находятся крупный выбранный день, круговой недельный прогресс, главное дело и цель недели. В нижнем ряду одновременно показываются семь карточек дней.

Линейная полоса недельного прогресса заменена круговой диаграммой с теми же доступными атрибутами `progressbar`. В каждую дневную карточку добавлен небольшой круговой процент выполнения, вычисляемый из уже существующих задач дня; новых пользовательских данных эта визуализация не создаёт. Мятная шкала 0–5 сохранена. Новая компоновка синхронно зафиксирована в `tz.md`.

**Результат ручной проверки этой итерации: не принят.** Реализация оказалась недостаточно похожа на референс, потому что сохранила крупную карточку выбранного дня. На референсе верхняя крупная область отведена недельной аналитике, а семь дней представлены снизу как равноправные полноценные карточки. Перед следующей переработкой необходимо явно выбрать между точным направлением референса и прежней концепцией «день в фокусе»; текущую третью итерацию нельзя считать утверждённым визуальным решением.

### Четвёртая доработка шага 1 после уточнения референса

Пользователь выбрал структуру, максимально близкую к референсу, но без аналитического графика, аккаунта, выбора языка и отдельных страниц. Прежняя постоянно видимая крупная карточка выбранного дня удалена из основного экрана. Верхний ряд теперь состоит из главного дела недели, кругового недельного прогресса и цели недели. Нижний ряд содержит семь равноправных дневных карточек; сегодняшний день немного шире и выделен сильнее.

Дневные карточки показывают краткое содержимое. Нажатие на карточку открывает отдельное модальное окно подробностей дня; именно там в следующих шагах будут добавление и редактирование задач и заметка дня. Изменения внесены в `index.html`, `styles.css`, `script.js` и синхронно отражены в `tz.md`. Результат требует новой ручной визуальной проверки пользователя.

При первой проверке четвёртой итерации обнаружен технический сбой: браузер загрузил новые `index.html` и CSS вместе с закэшированной версией `script.js`. Скрипт обращался к уже удалённому элементу старой полосы прогресса, прекращал выполнение до создания семи дневных карточек, поэтому страница выглядела сломанной. Для ресурсов `styles.css` и `script.js` добавлен явный параметр версии, чтобы браузер гарантированно загружал согласованный комплект файлов после изменений. После исправления обязательны повторная проверка консоли, фактический скриншот и открытие карточки дня.

После исправления страница проверена в реальном браузере при области просмотра `1280 × 720`: отображаются семь дневных карточек и круговой недельный прогресс, общая вертикальная прокрутка отсутствует (`scrollHeight` равен высоте окна). Нажатие на карточку понедельника открыло модальное окно с заголовком «Понедельник», кнопка закрытия сработала. Дополнительная чистая загрузка в новой вкладке завершилась без ошибок и предупреждений консоли. Технический сбой устранён.

### Пятая доработка шага 1 по уточнённой разметке референса

Пользователь уточнил назначение обведённой области референса: это должна быть крупная область выбранного дня, а не аналитический график или главное дело недели. Верхний ряд снова содержит выбранный день слева, но теперь следует пропорциям референса: рядом находятся две отдельные вертикально вытянутые области — круговой недельный прогресс со строками «Выполнено», «Осталось», «Всего задач» и карточка цели недели. Главное дело недели компактно размещено внутри правой карточки.

Нижний ряд растянут на всю оставшуюся высоту и содержит семь более высоких дневных карточек. Нажатие на день больше не открывает модальное окно: оно обновляет крупную область выбранного дня слева, что соответствует уточнённому сценарию. Для ширины от 821 px сетка занимает ровно доступную высоту окна, `body` не прокручивается, а возможное переполнение остаётся только внутри списка задач. Порог двухстрочной шапки снижен до 820 px, чтобы при ширине окна пользователя около 1077 px шапка оставалась компактной в один ряд. Версии CSS и JavaScript обновлены для защиты от старого кэша.

Пятая итерация проверена в реальном браузере при области `1078 × 927`, соответствующей пользовательскому скриншоту. Шапка занимает 80 px и остаётся в одну строку, верхний ряд — 365 px, нижняя область дневных карточек — 428 px. Отображаются все семь вытянутых карточек, общая вертикальная прокрутка отсутствует, пустой список выбранного дня не показывает внутреннюю полосу прокрутки. Нажатие на понедельник изменило заголовок главной области на «Понедельник», выбранной осталась ровно одна карточка. Ошибок и предупреждений консоли нет.
