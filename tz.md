# Техническое задание: веб-приложение «Мой квест на неделю»

## 1. Назначение документа

Документ содержит полное техническое задание на первую версию персонального недельного планировщика. Он предназначен для нейросети или разработчика, которые будут создавать приложение.

Если реализация не противоречит этому документу, дополнительные уточнения у заказчика не требуются. При технической неоднозначности следует выбирать самое простое решение без добавления новых функций.

## 2. Назначение продукта

«Мой квест на неделю» — однопользовательское локальное веб-приложение для быстрого планирования задач на неделю.

Продукт должен помогать:

- быстро записывать задачу только по названию;
- видеть выбранный день крупным планом и всю неделю одновременно;
- хранить задачи без назначенной даты во «Входящих»;
- переносить и сортировать задачи перетаскиванием;
- замечать невыполненные задачи текущей недели;
- автоматически подхватывать незавершённые дела при переходе на новую неделю;
- видеть спокойную статистику выполнения;
- хранить данные без регистрации, сервера и базы данных.

## 3. Пользователь и права

В продукте существует одна роль — **пользователь устройства**.

Авторизация, учётные записи, совместный доступ и разграничение прав отсутствуют. Пользователь может читать, создавать, изменять, перемещать, выполнять и удалять все данные приложения.

## 4. Технические ограничения

### 4.1. Состав проекта

Приложение должно состоять ровно из трёх основных файлов:

- `index.html` — структура страницы;
- `styles.css` — все стили и адаптивность;
- `script.js` — вся логика, состояние и работа с `localStorage`.

Не создавать серверную часть, базу данных, систему сборки, фреймворк или дополнительные исходные файлы. Не использовать внешние библиотеки и CDN. Приложение должно запускаться простым открытием `index.html` в современном браузере.

Запрет на библиотеки является осознанным требованием первой версии: приложение должно оставаться автономным, работать без сети и соответствовать исходному формату из трёх локальных файлов. Подключение Vue.js, Alpine.js или библиотеки drag-and-drop через CDN не допускается.

Чтобы единственный файл `script.js` оставался читаемым, код внутри него необходимо разделить на явно обозначенные логические секции:

1. константы и схема начального состояния;
2. утилиты локальных дат и недель;
3. чтение, проверка и запись хранилища;
4. операции над состоянием;
5. вычисляемые выборки и счётчики;
6. отрисовка интерфейса;
7. обработчики пользовательских действий;
8. drag-and-drop;
9. модальные окна и уведомления;
10. инициализация приложения.

Не дублировать бизнес-логику внутри обработчиков DOM-событий. Создание, изменение, перемещение и удаление сущностей выполнять через отдельные функции операций над состоянием. Для повторяющихся элементов использовать делегирование событий. Код обернуть в ES-модуль (`<script type="module">`) либо в замкнутую область видимости, не создавая изменяемых глобальных переменных.

### 4.2. Хранение

Все пользовательские данные хранятся в `localStorage` в одном JSON-объекте под ключом:

```text
myWeeklyPlanner
```

У объекта обязательно должно быть поле `schemaVersion`. Версия первой схемы — `1`.

Запись в `localStorage` выполняется после каждого изменения данных. Для текстовой заметки дня допускается отложенная запись через 300–500 мс после последнего ввода.

Если данных ещё нет, приложение создаёт пустое начальное состояние. Если JSON повреждён или имеет неподдерживаемую структуру, приложение не должно падать: нужно сохранить повреждённое значение под резервным ключом с временной меткой, создать чистое состояние и показать понятное уведомление.

### 4.2.1. Одновременная работа в нескольких вкладках

Приложение должно отслеживать изменение ключа `myWeeklyPlanner` в других вкладках через событие `storage`.

Для этого:

- при открытии каждая вкладка создаёт уникальный `tabId`, существующий только до закрытия вкладки;
- корневое состояние содержит служебные поля `revision`, `updatedAt` и `lastWriterId`;
- перед каждой записью вкладка повторно читает актуальный объект из `localStorage`, применяет к нему только текущую целевую операцию, увеличивает `revision` на единицу, обновляет `updatedAt` и записывает свой `tabId` в `lastWriterId`;
- изменения разных сущностей должны объединяться на уровне операции: например, редактирование задачи в одной вкладке не должно затирать добавление другой задачи во второй вкладке;
- после события `storage` вкладка принимает более новую ревизию, обновляет состояние и перерисовывает затронутые области;
- собственная запись, определённая по `lastWriterId`, не обрабатывается как внешнее изменение;
- если в момент внешнего изменения пользователь редактирует поле, его незавершённый текст не затирается; остальные данные обновляются, а рядом показывается сообщение `Данные изменились в другой вкладке`;
- при сохранении открытого редактора изменение применяется к самому свежему состоянию из хранилища;
- если одна и та же сущность изменена в двух вкладках, побеждает последнее успешно сохранённое изменение; автоматическое посимвольное объединение текста не выполняется;
- если сущность была удалена в другой вкладке, открытый редактор закрывается, а удалённая сущность не создаётся повторно;
- при одновременном редактировании заметки одной даты сохраняется последняя успешно записанная полная версия заметки;
- при внешнем полном удалении данных другие вкладки сбрасывают состояние, закрывают редакторы и показывают уведомление;
- автоматический перенос недели остаётся идемпотентным во всех вкладках благодаря `carryoverKey` и `carryoverLog`.

Если доступен Web Locks API, операции записи следует дополнительно выполнять внутри блокировки с именем `myWeeklyPlanner-write`. Если API недоступен, применяется описанная схема «прочитать актуальное состояние → применить одну операцию → записать». Полностью атомарные конкурентные транзакции `localStorage` не поддерживает, поэтому для редкого конфликта одной сущности явно применяется правило «последняя запись побеждает».

### 4.3. Дата и время

- Использовать локальные дату и время устройства.
- Не использовать серверное время.
- Неделя начинается в понедельник и заканчивается в воскресенье.
- На экране всегда представлены ровно семь дней.
- Даты задач хранить как локальные календарные даты в формате `YYYY-MM-DD`.
- Не преобразовывать календарную дату через UTC таким образом, чтобы она могла сместиться на соседний день.
- Интерфейс и формат дат — русские.

## 5. Границы первой версии

### 5.1. В первую версию входят

- недельный план из семи дней;
- крупный фокус выбранного дня;
- «Входящие» для задач без даты;
- задачи с названием, заметкой, категорией и маркером «Важно»;
- главная задача недели;
- цель недели;
- одна текстовая заметка на каждый день;
- выполнение, редактирование, удаление и сортировка задач;
- перетаскивание задач между днями и «Входящими»;
- просроченные задачи внутри текущей недели;
- автоматическое копирование незавершённых задач завершившейся недели;
- навигация между неделями;
- счётчики выполнения и поддерживающие фразы;
- настройки первой версии;
- отмена последнего удаления;
- адаптивное отображение на ноутбуке и телефоне;
- сохранение данных в `localStorage`.

### 5.2. В первую версию не входят

- покупки, идеи, список «Когда-нибудь» и трекер привычек;
- повторяющиеся задачи;
- время начала, дедлайн и длительность задачи;
- напоминания и системные уведомления;
- теги помимо одной категории;
- несколько уровней приоритета;
- поиск и фильтрация;
- экспорт и импорт резервной копии;
- синхронизация между устройствами;
- регистрация и совместная работа;
- сервер, API и база данных;
- форматирование текста заметки;
- календарный вид месяца.

## 6. Информационная архитектура

Приложение состоит из одного экрана со следующими областями:

1. Шапка приложения.
2. Блок главной задачи и цели открытой недели.
3. Центральная карточка выбранного дня.
4. Компактная карта всех семи дней недели.
5. Выдвижная панель «Входящие».
6. Блок просроченных задач текущей недели.
7. Панель настроек.
8. Всплывающие окна редактирования.
9. Временные уведомления с возможностью отмены удаления.

На ноутбуке используется двухуровневая компоновка в стиле недельной панели. В верхнем ряду крупная область выбранного дня находится слева, узкая вертикальная карточка кругового недельного прогресса со статистикой — в центре, а высокая карточка цели и главного дела недели — справа. Отдельный аналитический график не используется. В нижнем ряду одновременно показываются семь вертикально вытянутых карточек дней; сегодняшний день немного шире остальных и дополнительно выделен. Нажатие на дневную карточку выбирает её и обновляет крупную область дня слева. Основная рабочая область заполняет доступную высоту окна без прокрутки всей страницы; при фактическом переполнении прокручивается только внутренний список задач. «Входящие» открываются справа как выдвижная панель поверх страницы.

## 7. Шапка приложения

Шапка содержит:

- название «Мой квест на неделю»;
- диапазон дат открытой недели;
- кнопку перехода к предыдущей неделе;
- кнопку перехода к следующей неделе;
- кнопку «Сегодня»;
- кнопку открытия «Входящих» с числом активных входящих задач;
- кнопку настроек;

Недельный счётчик выполнения расположен не в шапке, а в отдельной узкой карточке прогресса центральной панели.

### 7.1. Навигация по неделям

- Стрелка влево открывает предыдущую неделю.
- Стрелка вправо открывает следующую неделю.
- Кнопка «Сегодня» открывает текущую неделю и выбирает сегодняшний день.
- Диапазон отображается по-русски, например: `17–23 августа 2026` или `31 августа — 6 сентября 2026`.
- Переход между неделями не изменяет задачи.
- После перезагрузки всегда открывается текущая неделя и выбирается сегодняшний день, независимо от того, какая неделя была открыта ранее.

### 7.2. Выбранный день

- При первом запуске и после перезагрузки выбран сегодняшний день.
- Нажатие на карточку любого дня открытой недели делает его выбранным.
- Выбранный день становится содержимым центральной крупной карточки.
- В прошлой или будущей неделе первым выбранным днём после навигации становится понедельник этой недели.
- При возвращении кнопкой «Сегодня» выбирается текущая дата.

## 8. Центральная карточка дня

Центральная карточка показывает:

- полное название дня недели;
- дату;
- отметку «Сегодня», если это текущая дата;
- дневной счётчик: выполнено активных и общее число задач дня;
- поле быстрого добавления задачи;
- список задач выбранного дня;
- одну заметку дня.

### 8.1. Быстрое добавление задачи

- Поле содержит подсказку `Добавить задачу и нажать Enter`.
- Нажатие `Enter` создаёт задачу в выбранном дне.
- Пустая строка или строка только из пробелов не создаёт задачу.
- Пробелы в начале и конце удаляются.
- Максимальная длина названия — 200 символов.
- После успешного добавления поле очищается и сохраняет фокус.
- Новая задача добавляется в конец активной части списка.
- `Shift+Enter` не используется, поскольку поле однострочное.

Отдельных полей быстрого ввода в компактных карточках дней нет.

### 8.2. Заметка дня

Для каждой календарной даты существует одна независимая текстовая заметка.

- Заметка представлена многострочным полем.
- Подсказка: `Короткая заметка для этого дня…`.
- Содержимое сохраняется автоматически.
- Максимальная длина — 5000 символов.
- Форматирование, чекбоксы и вложения отсутствуют.
- Пустая заметка не должна создавать лишнюю запись в данных.

## 9. Компактная карта недели

Лента содержит семь карточек с понедельника по воскресенье. В каждой карточке отображаются:

- сокращённое название дня недели;
- число месяца;
- отметка текущего дня;
- до трёх первых активных задач;
- строка `+N ещё`, если активных задач больше трёх;
- количество выполненных задач и общее количество задач дня.

Поведение:

- нажатие на карточку выбирает этот день;
- выполненные задачи в кратком перечне не показываются;
- карточка выбранного дня визуально выделяется;
- текущий день имеет дополнительную спокойную отметку, даже если выбран другой день;
- на ноутбуке карточки размещаются единым нижним рядом и показываются все одновременно;
- все карточки равноправны, но карточка сегодняшнего дня немного шире и заметнее остальных;
- при переполнении прокручивается только внутренняя область карты, а не вся страница;
- на телефоне карточки превращаются в горизонтально прокручиваемую ленту;
- в каждой карточке показывается небольшой круговой процент выполнения, вычисленный из задач дня;
- в карточке показывается краткий список, а полное содержимое выбранного дня отображается в крупной верхней области;
- компактная карточка не содержит кнопки создания задачи.

## 10. Сущность «Задача»

### 10.1. Поля задачи

Каждая задача содержит:

```text
id                уникальный строковый идентификатор
title             обязательное название, до 200 символов
note              необязательный текст, до 2000 символов
categoryId        идентификатор категории или null
isImportant       true/false
isCompleted       true/false
completedAt       временная метка или null
date              YYYY-MM-DD или null для «Входящих»
order             число для ручной сортировки
createdAt         временная метка создания
updatedAt         временная метка последнего изменения
sourceTaskId      id исходной задачи при копировании или null
carryoverKey      идентификатор автоматического переноса или null
```

Идентификатор должен создаваться через `crypto.randomUUID()`, а при отсутствии поддержки — через безопасный локальный генератор с временной меткой и случайной частью.

### 10.2. Карточка задачи

Карточка содержит:

- чекбокс выполнения;
- название;
- метку категории, если категория назначена;
- спокойный значок «Важно», если маркер установлен;
- индикатор наличия заметки;
- область или кнопку для начала перетаскивания;
- меню действий: редактировать и удалить.

Текст пользователя выводить как текст, а не как HTML.

### 10.3. Выполнение

При включении чекбокса:

- `isCompleted` становится `true`;
- устанавливается `completedAt`;
- задача перемещается вниз списка после всех активных задач;
- название зачёркивается;
- карточка становится полупрозрачной;
- обновляются дневной и недельный счётчики.

При снятии отметки:

- `isCompleted` становится `false`;
- `completedAt` очищается;
- задача возвращается в конец активной части списка;
- счётчики пересчитываются.

Настройка «Показывать выполненные» управляет видимостью выполненных карточек. Скрытие не удаляет данные. Выполненные задачи прошлых недель хранятся бессрочно, пока пользователь сам их не удалит или не очистит все данные.

### 10.4. Маркер «Важно»

- Маркер устанавливается и снимается при редактировании задачи.
- Он только визуально выделяет задачу небольшим значком или тонким акцентом.
- Он не меняет порядок автоматически.
- Он не влияет на счётчики, переносы и просроченность.
- Это бинарный признак; других уровней приоритета нет.

### 10.5. Редактирование

- Двойной щелчок по названию или команда «Переименовать» включает редактирование названия прямо в карточке.
- `Enter` сохраняет название, `Escape` отменяет изменение.
- Пустое название не сохраняется; показывается короткая ошибка.
- Кнопка или команда «Подробнее» открывает небольшое модальное окно.
- В модальном окне доступны название, заметка, категория и флажок «Важно».
- Кнопка «Сохранить» применяет изменения.
- Кнопка «Отмена», клавиша `Escape` и нажатие на затемнение закрывают окно без сохранения.

### 10.6. Удаление

- Команда удаления сразу удаляет задачу без отдельного подтверждения.
- После удаления появляется уведомление `Задача удалена` с кнопкой `Отменить`.
- Уведомление доступно 10 секунд.
- В каждый момент можно отменить только последнее удаление.
- Новое удаление заменяет предыдущую запись отмены.
- При отмене сущность восстанавливается с прежними данными и максимально близкой исходной позицией.

## 11. Сортировка и перенос задач

### 11.1. Перетаскивание

Пользователь может перетащить активную или выполненную задачу:

- внутри одного дня для изменения порядка;
- из одного дня в другой;
- из дня во «Входящие»;
- из «Входящих» в любой день;
- из блока просроченных в день текущей недели; для просроченной задачи это специальное действие копирования, которое сохраняет исходник на прежней дате.

Во время перетаскивания:

- допустимая область назначения подсвечивается;
- виден placeholder позиции;
- после отпускания задача сразу сохраняется;
- перемещение между списками меняет поле `date`;
- обычное перемещение не создаёт копию;
- перетаскивание из блока просроченных создаёт невыполненную копию по правилам раздела 14, а исходная задача остаётся на прежней дате;
- если для просроченной задачи уже существует копия, перед повторным копированием показывается подтверждение.

### 11.2. Порядок

- Активные задачи всегда отображаются перед выполненными.
- Внутри каждой группы действует ручной порядок.
- Перетаскивание выполненной задачи в активную область не снимает выполнение.
- Маркер «Важно» не влияет на порядок.

### 11.3. Запасной способ перемещения

В меню каждой задачи должна быть команда `Переместить`. Она открывает список назначений:

- «Входящие»;
- семь дней открытой недели;
- выбор конкретной даты через стандартное поле даты.

Команда обязательна для доступности и использования на телефоне, где перетаскивание может быть неудобным.

## 12. Входящие

«Входящие» — список задач без даты.

### 12.1. Открытие

- Панель открывается кнопкой в шапке.
- Повторное нажатие, кнопка закрытия или `Escape` закрывают панель.
- В кнопке показывается количество невыполненных входящих задач.

### 12.2. Содержимое

Панель содержит:

- заголовок;
- поле быстрого добавления;
- список задач;
- пустое состояние, если задач нет.

Нажатие `Enter` создаёт задачу с `date: null`. Остальные свойства и действия совпадают с обычной задачей. Входящие задачи не считаются просроченными и не участвуют в недельном прогрессе.

## 13. Категории

Первая версия использует фиксированные категории:

| ID | Название | Визуальный цвет |
|---|---|---|
| `work` | Работа | приглушённый терракотовый |
| `personal` | Личное | пыльно-розовый |
| `home` | Дом | песочно-жёлтый |
| `study` | Учёба | приглушённый оливковый |

Также всегда доступно состояние «Без категории».

Точные доступные оттенки задаются в CSS и должны иметь достаточный контраст с текстом. Яркие чистые цвета не использовать.

В настройках пользователь может включать и скрывать фиксированные категории в окне выбора. Скрытие категории:

- не удаляет её из уже существующих задач;
- не скрывает соответствующие задачи;
- убирает категорию только из списка для нового назначения;
- категория снова доступна после включения.

Создавать, удалять, переименовывать и перекрашивать категории в первой версии нельзя.

## 14. Просроченные задачи и перенос между неделями

### 14.1. Просроченные внутри текущей недели

Просроченной считается невыполненная задача, если:

- у неё есть дата;
- дата относится к текущей календарной неделе;
- дата раньше сегодняшней локальной даты.

Задачи прошлых недель не показываются в текущем блоке просроченных. В будущих и прошлых неделях блок не отображается.

Блок `Остались с прошлых дней` показывается на экране текущей недели над основной рабочей областью. Его можно свернуть. В заголовке всегда видно число задач.

### 14.2. Действия с просроченной задачей

Доступны:

- `Копировать на сегодня`;
- `Копировать на другой день`;
- `Копировать во Входящие`;
- отметить исходную задачу выполненной;
- редактировать исходную задачу;
- удалить исходную задачу.

При копировании:

- создаётся новая задача с новым `id`;
- поля названия, заметки, категории и «Важно» копируются;
- копия создаётся невыполненной;
- `sourceTaskId` содержит id исходной задачи;
- исходная задача остаётся на прежней дате и продолжает отображаться как просроченная, пока не будет выполнена или удалена;
- рядом с исходной задачей показывается спокойная отметка, что для неё уже создана копия, чтобы пользователь не делал это случайно повторно;
- повторное копирование разрешено только после явного подтверждения.

### 14.3. Автоматический перенос незавершённых задач недели

При первом открытии приложения после начала новой недели необходимо проверить непосредственно предыдущую календарную неделю.

Все её невыполненные задачи с назначенной датой автоматически **копируются** на понедельник текущей недели. Исходные задачи сохраняются в прошлой неделе. Выполненные задачи и задачи из «Входящих» не копируются.

Правила:

- операция выполняется не более одного раза для пары «исходная неделя → следующая неделя»;
- каждая копия получает новый `id`, дату понедельника новой недели и `sourceTaskId` исходной задачи;
- копия всегда создаётся невыполненной;
- название, заметка, категория и «Важно» сохраняются;
- `carryoverKey` должен однозначно связывать исходную задачу и неделю назначения;
- повторная загрузка страницы не создаёт дубликаты;
- если пользователь впервые вернулся через несколько недель, обрабатывается только непосредственно предыдущая неделя относительно текущей даты, а не вся история;
- после операции показывается сообщение, например: `3 незавершённые задачи добавлены на понедельник`;
- если копировать нечего, сообщение не показывается.

Перенос происходит только для реальной текущей недели устройства, а не при обычном просмотре будущей недели стрелками.

## 15. Главная задача недели

Для каждой недели существует не более одной главной задачи.

Поля:

```text
id
weekStart
title
isCompleted
createdAt
updatedAt
```

Поведение:

- блок показывается над центральной карточкой;
- если задача не создана, отображается приглашение `Выбрать главную задачу недели`;
- обязательным является только название до 200 символов;
- главная задача не имеет конкретного дня, заметки, категории и маркера «Важно»;
- её нельзя перетаскивать;
- её можно выполнить, вернуть в активное состояние, переименовать и удалить;
- команда `Перенести на другую неделю` создаёт её копию в выбранной неделе после подтверждения;
- если в целевой неделе уже есть главная задача, пользователь должен подтвердить её замену;
- перенос создаёт копию, исходная главная задача остаётся в своей неделе;
- выполнение главной задачи не входит в обычный недельный счётчик задач; рядом с ней показывается собственное состояние.

## 16. Цель недели

Для каждой недели существует одна короткая текстовая цель.

- Максимальная длина — 300 символов.
- Цель не имеет чекбокса выполнения.
- Она редактируется прямо в блоке недели.
- Сохранение происходит при потере фокуса и по `Ctrl+Enter`.
- Пустое значение означает отсутствие цели и не создаёт отдельную запись.
- Цель не копируется автоматически между неделями.

Главная задача недели — конкретное выполнимое дело, а цель недели — свободная формулировка желаемого результата. Интерфейс должен визуально различать эти сущности.

## 17. Счётчики и мотивация

### 17.1. Дневной счётчик

Формат: `Выполнено X из Y`.

- Учитываются только задачи выбранной даты.
- Входящие и главная задача недели не учитываются.
- `Y` включает активные и выполненные задачи.

### 17.2. Недельный счётчик

Внутри круговой карточки прогресса показывается компактный формат `X из Y`. Подписи рядом отдельно показывают количество выполненных, оставшихся и всех задач недели.

- Учитываются задачи всех семи дат открытой недели.
- Входящие и главная задача недели не учитываются.
- Просроченная исходная задача и созданная копия являются отдельными задачами и учитываются каждая на своей дате.

### 17.3. Поддерживающие фразы

Фраза показывается в центральной карточке, если соответствующая настройка включена.

Использовать фиксированный локальный набор без обращения к сети. Выбор зависит от прогресса выбранного дня:

- задач нет: `Добавьте первую задачу на этот день.`
- выполнено 0% при одной задаче: `Начните с этой задачи.`
- выполнено 0% при нескольких задачах: `В списке N задач — начните с любой.`
- выполнено больше 0%, но меньше 50%: `Хорошее начало. Осталось задач: N.`
- выполнено от 50% до 99%: `Большая часть готова. Осталась 1 задача.` или `Большая часть готова. Осталось задач: N.`
- выполнено 100%: `На сегодня всё выполнено.`

В карточке недельного прогресса дополнительно показывается короткая фраза, вычисленная из недельного счётчика. Она использует тот же спокойный тон, не содержит упрёков и скрывается тем же переключателем настроек.

Фразы не должны содержать упрёков, серий дней, штрафов или соревновательных баллов.

## 18. Настройки

Панель настроек содержит:

1. Включение и скрытие фиксированных категорий.
2. Переключатель `Показывать выполненные задачи`, по умолчанию включён.
3. Переключатель `Показывать поддерживающие фразы`, по умолчанию включён.
4. Кнопку `Удалить все данные`.

### 18.1. Полное удаление данных

- Перед удалением обязательно открыть подтверждение.
- Текст должен прямо сообщать, что будут удалены все задачи, заметки, цели и настройки и что отменить действие нельзя.
- Кнопки: `Отмена` и `Удалить всё`.
- После подтверждения удалить ключ приложения из `localStorage`, очистить состояние и показать пустой текущий план.
- Операция не участвует в механизме отмены удаления.

## 19. Универсальная отмена удаления

Отмена применяется к удалению:

- обычной задачи;
- главной задачи недели;
- цели недели, если для неё предусмотрена отдельная команда очистки;
- заметки дня, если для неё предусмотрена отдельная команда очистки.

Технические требования:

- хранить снимок только последней удалённой сущности в оперативном состоянии страницы;
- показывать уведомление 10 секунд;
- после перезагрузки страницы отмена недоступна;
- полная очистка приложения не отменяется;
- закрытие уведомления вручную отменяет возможность восстановления.

## 20. Состояния пустых списков и ошибки

Использовать короткие понятные тексты:

- день без задач: `На этот день пока ничего не запланировано.`;
- пустые «Входящие»: `Здесь можно быстро сохранить задачу без даты.`;
- нет просроченных задач: блок полностью скрыт;
- неделя без главной задачи: `Выберите одно главное дело этой недели.`;
- неделя без цели: `Что хотелось бы получить от этой недели?`.

Ошибки валидации показываются рядом с соответствующим полем. Ошибки сохранения в `localStorage` показываются общим уведомлением: данные остаются в оперативном состоянии страницы, но пользователь предупреждается, что после перезагрузки они могут быть потеряны.

## 21. Адаптивность

### 21.1. Ноутбук и широкий экран

- Основная целевая ширина — от 1024 px.
- В верхнем ряду расположены крупная область выбранного дня слева, узкая высокая карточка кругового недельного прогресса со статистикой по центру и цель недели с главным делом справа; аналитического графика нет.
- В нижнем ряду расположены семь вертикально вытянутых карточек дней с круговым процентом выполнения; сегодняшний день немного шире.
- Нажатие на дневную карточку обновляет выбранный день в верхней области.
- При ширине от 821 px основная страница не имеет вертикальной прокрутки и укладывается по высоте окна; переполняться и прокручиваться могут только внутренние списки с содержимым.
- «Входящие» открываются справа.
- Максимальная ширина основного содержимого ограничена, чтобы строки не становились чрезмерно длинными.

### 21.2. Планшет и телефон

- При ширине меньше 768 px элементы шапки компактно переносятся.
- Центральная карточка занимает почти всю ширину.
- Недельная лента прокручивается горизонтально с удобным попаданием карточек в область просмотра.
- «Входящие» открываются полноэкранной или почти полноэкранной панелью.
- Команды карточки доступны без наведения мыши.
- Обязательно доступна команда `Переместить`, даже если drag-and-drop не работает на конкретном сенсорном устройстве.
- Минимальный размер интерактивной области — около 44 × 44 px.

## 22. Визуальные требования

Стиль — спокойный мятно-зелёный, свежий, но не неоновый.

### 22.1. Палитра

Использовать мятную шкалу от 0 до 5:

- уровень 0 — почти белый бледно-мятный основной фон;
- уровень 1 — светло-мятные вторичные поверхности и выбранные области большой площади;
- уровень 2 — мягкие мятные границы, подложки и спокойные карточки;
- уровень 3 — более заметные рамки и состояния выбора;
- уровень 4 — активные кнопки и заполнение полосы прогресса;
- уровень 5 — небольшие сильные акценты, завершённые состояния и конец градиента прогресса.

Карточки могут быть почти белыми с холодным мятным оттенком. Основной текст — тёмный зелёно-графитовый, вторичный — приглушённый серо-зелёный. Ошибки выделяются приглушённым коралловым цветом. Не использовать бежевую основу, неоновые оттенки и большие заливки уровня 5.

### 22.2. Компоненты

- мягкие скругления;
- лёгкие тени без сильного контраста;
- достаточно свободного пространства;
- выбранный день выделяется размером, рамкой и мягким фоном;
- текущий день имеет отдельную небольшую отметку;
- анимации короткие, около 150–250 мс;
- учитывать `prefers-reduced-motion` и отключать необязательные анимации.

### 22.3. Типографика

Не загружать внешние шрифты. Использовать системный стек:

```css
font-family: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Arial, sans-serif;
```

- Основной размер текста — `16px`.
- Минимальный размер вспомогательного текста — `14px`.
- Основной межстрочный интервал — `1.5`.
- Для заголовков использовать тот же стек с весом `600` или `700`, без декоративного шрифта.
- Размеры задавать преимущественно в `rem`, чтобы масштабирование браузера корректно влияло на интерфейс.
- Длинные названия задач должны переноситься по словам и не выходить за границы карточки.

## 23. Доступность и управление

- Все интерактивные элементы доступны с клавиатуры.
- У каждой кнопки есть текстовая подпись или `aria-label` на русском языке.
- Видимый фокус клавиатуры обязателен.
- Модальное окно удерживает фокус внутри себя и возвращает его вызвавшему элементу после закрытия.
- `Escape` закрывает верхнюю открытую панель или модальное окно.
- Чекбоксы должны быть нативными или полностью корректно размеченными.
- Нельзя передавать смысл только цветом: категории имеют текст, «Важно» имеет значок и подпись для экранного диктора.
- Контраст текста и элементов управления должен соответствовать WCAG 2.1 AA.
- Перемещение задачи должно быть возможно без drag-and-drop.

## 24. Структура состояния `localStorage`

Рекомендуемая обязательная структура:

```json
{
  "schemaVersion": 1,
  "revision": 0,
  "updatedAt": null,
  "lastWriterId": null,
  "tasks": [],
  "dayNotes": {},
  "weekGoals": {},
  "weekMainTasks": {},
  "carryoverLog": {},
  "settings": {
    "showCompleted": true,
    "showMotivation": true,
    "enabledCategoryIds": ["work", "personal", "home", "study"]
  }
}
```

Ключи `dayNotes` — даты `YYYY-MM-DD`. Ключи `weekGoals`, `weekMainTasks` и `carryoverLog` — даты понедельников соответствующих недель в формате `YYYY-MM-DD`.

Не хранить в `localStorage` временное состояние интерфейса: открытые модальные окна, выбранный день, открытую неделю, уведомление отмены и состояние фокуса.

`lastWriterId` является служебным идентификатором последней записавшей вкладки, а не постоянным идентификатором пользователя. Новая вкладка создаёт собственный `tabId` при каждом открытии.

## 25. Производительность и надёжность

- Интерфейс должен корректно работать как минимум с 1000 сохранёнными задачами.
- Обработчики событий не должны дублироваться при повторной отрисовке.
- Любое изменение сначала применяется к единому состоянию, затем сохраняется и отображается.
- Счётчики всегда вычисляются из актуальных данных, а не хранятся отдельными изменяемыми значениями.
- Автоматический перенос недели должен быть идемпотентным и не создавать повторных копий.
- Пользовательский текст нельзя вставлять через небезопасный `innerHTML`.
- Ошибка одной записи не должна ломать отображение остальных данных.
- Изменение в одной вкладке должно появляться в другой открытой вкладке без перезагрузки страницы.
- Операция над одной сущностью должна применяться к последней прочитанной версии состояния и не затирать несвязанные изменения другой вкладки.

## 26. Сценарии использования

### UC-01. Первый запуск

**Предусловие:** данных приложения нет.

1. Пользователь открывает `index.html`.
2. Приложение определяет локальную текущую дату.
3. Открывается текущая неделя с понедельника по воскресенье.
4. Крупным выбран сегодняшний день.
5. Показываются пустые состояния и приглашения создать цель и главную задачу.

**Результат:** приложение готово к вводу без регистрации и настройки.

### UC-02. Быстро добавить задачу на выбранный день

1. Пользователь выбирает день в недельной карте.
2. Вводит название в центральное поле.
3. Нажимает `Enter`.

**Результат:** задача добавлена в выбранный день, сохранена и видна в списке.

### UC-03. Добавить задачу во «Входящие»

1. Пользователь открывает «Входящие».
2. Вводит название.
3. Нажимает `Enter`.

**Результат:** создана задача без даты; счётчик входящих увеличен.

### UC-04. Дополнить задачу

1. Пользователь открывает «Подробнее» у задачи.
2. Добавляет заметку.
3. Выбирает доступную категорию.
4. При необходимости включает «Важно».
5. Нажимает «Сохранить».

**Результат:** карточка показывает категорию, важность и наличие заметки.

### UC-05. Переименовать задачу на месте

1. Пользователь дважды нажимает название.
2. Меняет текст.
3. Нажимает `Enter`.

**Результат:** новое непустое название сохранено.

### UC-06. Выполнить и вернуть задачу

1. Пользователь включает чекбокс.
2. Задача перемещается вниз, зачёркивается и становится полупрозрачной.
3. Пользователь снимает отметку.

**Результат:** задача снова активна и находится в конце активной части списка.

### UC-07. Изменить порядок задач

1. Пользователь захватывает карточку.
2. Перетаскивает её на новую позицию в том же списке.
3. Отпускает.

**Результат:** новый ручной порядок сохраняется после перезагрузки.

### UC-08. Перенести задачу в другой день

1. Пользователь перетаскивает задачу на карточку другого дня либо выбирает команду «Переместить».
2. Указывает день назначения.

**Результат:** дата исходной задачи изменена, копия не создаётся.

### UC-09. Распределить входящую задачу

1. Пользователь открывает «Входящие».
2. Перетаскивает задачу в день недели или использует «Переместить».

**Результат:** задача исчезает из входящих и появляется в выбранном дне.

### UC-10. Вернуть задачу во «Входящие»

1. Пользователь переносит датированную задачу во «Входящие».

**Результат:** дата задачи очищена; недельный прогресс пересчитан.

### UC-11. Удалить и восстановить задачу

1. Пользователь удаляет задачу.
2. Появляется уведомление на 10 секунд.
3. Пользователь нажимает «Отменить».

**Результат:** задача восстановлена с прежними полями и позицией.

### UC-12. Просмотреть другую неделю

1. Пользователь нажимает стрелку навигации.
2. Открывается соседняя неделя, выбран её понедельник.
3. Пользователь нажимает «Сегодня».

**Результат:** открывается текущая неделя и выбран сегодняшний день.

### UC-13. Обработать просроченную задачу текущей недели

1. Пользователь открывает блок `Остались с прошлых дней`.
2. Выбирает `Копировать на сегодня`.
3. Приложение создаёт копию на сегодня и помечает наличие копии у исходной задачи.
4. Пользователь при необходимости завершает или удаляет исходную задачу.

**Результат:** новая задача запланирована, история исходного дня сохранена.

### UC-14. Автоматически начать новую неделю

**Предусловие:** в непосредственно предыдущей неделе остались невыполненные датированные задачи, а перенос ещё не выполнялся.

1. Пользователь впервые открывает приложение в новой неделе.
2. Приложение однократно копирует незавершённые задачи на понедельник.
3. Показывается количество добавленных задач.

**Результат:** незавершённые дела доступны в новой неделе, исходные записи и история сохранены, повторная загрузка не создаёт дубликаты.

### UC-15. Задать главную задачу недели

1. Пользователь выбирает создание главной задачи.
2. Вводит название.
3. Сохраняет.
4. Позднее отмечает её выполненной.

**Результат:** главная задача закреплена за неделей и имеет собственное состояние выполнения.

### UC-16. Скопировать главную задачу в другую неделю

1. Пользователь выбирает `Перенести на другую неделю`.
2. Указывает неделю назначения.
3. Подтверждает действие.

**Результат:** в выбранной неделе создана копия, исходная задача сохранена.

### UC-17. Записать цель недели

1. Пользователь вводит короткую цель.
2. Уводит фокус или нажимает `Ctrl+Enter`.

**Результат:** цель сохранена для открытой недели.

### UC-18. Вести заметку дня

1. Пользователь выбирает день.
2. Вводит текст в заметку.
3. Прекращает ввод.

**Результат:** заметка автоматически сохраняется и восстанавливается при следующем открытии этой даты.

### UC-19. Скрыть выполненные задачи

1. Пользователь открывает настройки.
2. Выключает `Показывать выполненные задачи`.

**Результат:** выполненные карточки скрыты во всех списках, но сохранены и учитываются в прогрессе.

### UC-20. Отключить поддерживающие фразы

1. Пользователь выключает соответствующую настройку.

**Результат:** фразы скрыты, остальные элементы не меняются.

### UC-21. Управлять доступностью категорий

1. Пользователь выключает категорию в настройках.
2. Открывает редактирование новой задачи.

**Результат:** категория отсутствует среди доступных для назначения, но остаётся на старых задачах.

### UC-22. Полностью очистить приложение

1. Пользователь нажимает `Удалить все данные`.
2. Читает предупреждение.
3. Подтверждает необратимое удаление.

**Результат:** локальные данные удалены, приложение возвращено к чистому состоянию.

### UC-23. Перезагрузить страницу

1. Пользователь изменяет задачи и заметки.
2. Перезагружает страницу.

**Результат:** данные и ручной порядок восстановлены; открыта текущая неделя и выбран сегодняшний день.

### UC-24. Использовать приложение с клавиатуры

1. Пользователь перемещается клавишей `Tab`.
2. Добавляет и редактирует задачу.
3. Использует команду «Переместить» вместо перетаскивания.
4. Закрывает окно клавишей `Escape`.

**Результат:** основной функционал доступен без мыши.

### UC-25. Использовать приложение на телефоне

1. Пользователь открывает страницу на узком экране.
2. Выбирает день в горизонтальной мобильной ленте.
3. Добавляет задачу.
4. Переносит её через меню.

**Результат:** элементы не выходят за экран, кнопки доступны для касания, основной сценарий работает без точного drag-and-drop.

### UC-26. Работать в двух вкладках

1. Пользователь открывает приложение в двух вкладках одного браузерного профиля.
2. В первой вкладке добавляет задачу.
3. Вторая вкладка получает событие изменения хранилища и показывает новую задачу без перезагрузки.
4. Во второй вкладке пользователь изменяет другую задачу.
5. Первая вкладка получает это изменение, не теряя ранее добавленную задачу.
6. Если обе вкладки изменяют одну сущность, сохраняется последняя успешно записанная версия и показывается уведомление о внешнем изменении.

**Результат:** несвязанные изменения не затирают друг друга, а конфликт одной сущности разрешается по правилу «последняя запись побеждает».

## 27. Критерии приёмки

Приложение считается соответствующим ТЗ, если одновременно выполнены условия:

1. Проект состоит из `index.html`, `styles.css` и `script.js` и работает без сервера.
2. При запуске открывается текущая неделя из семи дней с понедельника.
3. Сегодняшний день выбран и показан крупно.
4. Любой день можно выбрать из недельной карты.
5. Задача создаётся по `Enter` и попадает именно в выбранный день.
6. Задачу можно создать во «Входящих» без даты.
7. Работают редактирование названия, заметки, категории и маркера «Важно».
8. Работают выполнение и обратное возвращение задачи.
9. Выполненные задачи перемещаются вниз, зачёркиваются и могут быть скрыты настройкой.
10. Работают ручная сортировка, перенос между днями и перенос во «Входящие».
11. Перенос доступен как перетаскиванием, так и через меню.
12. Просроченные задачи текущей недели собраны в отдельном блоке.
13. Ручная обработка просроченной задачи создаёт копию и сохраняет исходник.
14. В начале новой недели незавершённые задачи непосредственно предыдущей недели копируются на понедельник ровно один раз.
15. Главная задача и цель сохраняются отдельно для каждой недели.
16. Для каждой даты сохраняется отдельная автосохраняемая заметка.
17. Дневной и недельный счётчики пересчитываются корректно.
18. Удаление любой обычной сущности можно отменить в течение 10 секунд.
19. После перезагрузки все постоянные данные и порядок восстанавливаются.
20. После перезагрузки открывается сегодняшний день, а временное состояние интерфейса не восстанавливается.
21. Полное удаление данных требует явного подтверждения.
22. Интерфейс адаптируется к ширине телефона и не требует drag-and-drop.
23. Основные операции доступны с клавиатуры.
24. Пользовательский ввод не исполняется как HTML или JavaScript.
25. В консоли браузера нет необработанных ошибок при выполнении основных сценариев.
26. Изменения синхронизируются между двумя вкладками через `storage`; несвязанные операции не теряются, а конфликт одной сущности разрешается по описанному правилу.
